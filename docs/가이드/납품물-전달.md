# 납품물 전달 — **USB 없이 보낸다**

```text
문제        릴리스 폴더가 **1.94 GiB** 다. USB 를 들고 들어갈 수 없는 현장이 있다
1차선        릴리스 폴더째 **zip 하나** → 조각내 **릴리스 자산**으로. 작은 몫은 가지에
2차선        이미지 열 장을 **레지스트리**로 → tar 가 아예 필요 없어진다
            ⚠ 도커 방화벽이 막혀 있으면 못 쓴다 → 1차선으로 돌아간다
만드는 명령   pwsh -File scripts\release-deliver.ps1 -ReleaseId <릴리스ID>
⚠ 올리는 일은 스크립트가 하지 않는다 — **모양만 만들고 사람이 올린다**
```

---

## 왜 폴더째로 커밋할 수 없나 — **재서 정했다**

```text
파일당 100 MiB      GitHub 은 그보다 큰 파일이 들어오면 **push 를 막는다**(hard block).
                   robo-images.tar 1.82 GiB · 설치본 EXE 101.5 MiB → 둘 다 걸린다
push 당 2 GiB       한 번의 push 가 넘으면 거절된다
압축해도 안 준다     릴리스 전체 zip **98.4%** (1.94 GiB → 1.91 GiB).
                   도커 tar 안의 레이어가 이미 압축이다 — zip 은 **줄이려고**
                   하는 게 아니라 **한 파일로 묶으려고** 하는 것이다
```

### Git LFS 는? — **된다. 그런데 값을 치른다**

```text
파일당 한도   2 GB (Free·Pro) → 1.82 GiB 는 **들어간다**
월 할당      저장 10 GB · 전송 10 GB. 한 판이 1.8 GB 이므로
            **다섯 번 받으면 그 달 전송이 끝난다**
지불 수단 없이 넘기면   전송 초과 → 그 달 LFS 가 **계정 전체에서** 꺼진다
영구히 남는다  레포 역사에 들어가므로, 판을 올릴수록 clone 이 무거워진다
```

### `docker save` 로 tar 를 **되만드는 길은 안 된다**

솔깃한 생각이다 — 가지에 글만 올리고, 받는 쪽에서 tar 를 만들어 내게 하면
1.8 GiB 를 안 보내도 될 것 같다. **안 된다.**

```text
2026-10-29 실측
  1~2장을 같은 순서로 두 번 떠 보면   sha **같다** (재현된다)
  **열 장**을 같은 순서로 두 번 뜨면   sha **다르다** (크기는 같다)
    r1  a98f229dc564d8ee…   1,953,376,256 바이트
    r2  c16ed79c4d8050d8…   1,953,376,256 바이트
앱은 매니페스트의 imageArchiveSha256 을 검사한다
  → docker.image_archive_checksum_mismatch 로 **거절한다**
```

⚠ 적은 장수로 재 보면 "재현된다" 는 답이 나온다. **납품 장수(열 장)로 재야 한다.**

그리고 애초에 순환이다 — 스크립트가 돌려면 이미지 열 장이 그 기계에 **이미
있어야** 하는데, 있으면 **앱은 tar 를 아예 읽지 않는다**(아래 2차선 참고).

# 1차선 — 릴리스 폴더째 zip

## 1. 전달 모양을 만든다

```powershell
cd C:\Users\YSW\Desktop\robo-workspace
pwsh -File scripts\release-deliver.ps1 -ReleaseId <릴리스ID>
```

스크립트가 하는 일.

```text
① 온전한지 먼저 본다   SHA256SUMS 를 전부 다시 계산해 대조한다.
                     깨진 판으로 전달 모양을 만들어 올리면 받는 쪽에서야 안다
② 가른다              100 MiB 넘는 **파일**은 가지에 못 들어간다 → 표시만 한다
③ zip 한다            릴리스 폴더째. `tar.exe`(bsdtar)로 묶는다
                     ⚠ Compress-Archive 를 쓰지 않는다 — 2 GiB 급에서 느리고
                       메모리를 먹는다
                     zip 안의 항목 수를 원본 파일 수와 대조한다(반쪽 zip 방지)
④ 조각낸다            1.8 GiB 를 넘으면 **그 zip 을** 1 GiB 조각으로
⑤ 목록과 한 장         ASSETS.sha256 · README-전달.md (받는 쪽이 읽을 것)
```

**이렇게 나온다**

```text
_delivery\<릴리스ID>\
  repo\                     ← **가지에 담는 몫** (20 MB)
    central-server\         compose.yml · central-authority.env.example
                            README.md · **robo-central.sh** · runtime-manifest.json
    sbom\                   19.3 MB · 치명·고위험 0건
    robo-env.ps1 · runtime-manifest.json · SHA256SUMS
    ASSETS.sha256           자산 조각의 체크섬
    README-전달.md           **받는 쪽이 읽을 한 장**
  assets\                   ← **자산으로 올리는 몫** (커밋하지 않는다)
    <릴리스ID>.zip.part001   1.00 GiB
    <릴리스ID>.zip.part002   0.91 GiB
```

> ⚠ **`_delivery/` 는 `.gitignore` 에 있다.** 없으면 1 GiB 조각이 추적되어
> **굽기의 "작업 트리 0건" 게이트가 멈춘다.**

## 2. 가지에 올린다 — ⚠ **worktree 로 한다**

지금 작업 트리에 파일을 복사해 커밋하면 **다음 굽기가 "작업 트리 0건" 에서
멈춘다.** 스크립트가 이 명령들을 그대로 찍어 주므로 거기서 복사해 쓴다.

```powershell
$REL = "<릴리스ID>"
$WS  = "C:\Users\YSW\Desktop\robo-workspace"
$WT  = "C:\Users\YSW\Desktop\robo-delivery-$REL"

git -C $WS worktree add -b "delivery/$REL" $WT
New-Item -ItemType Directory -Force -Path "$WT\delivery\$REL" | Out-Null
robocopy "$WS\_delivery\$REL\repo" "$WT\delivery\$REL" /E
git -C $WT add "delivery/$REL"
git -C $WT commit -m "deliver: $REL — 가지에 담는 몫(자산 제외)"
git -C $WT push -u origin "delivery/$REL"
git -C $WS worktree remove $WT        # 끝나면 치운다
```

> ⚠⚠ **`.gitattributes` 에 `*.sh text eol=lf` 가 있어야 한다.** 없으면
> `core.autocrlf=true` 환경에서 새로 clone 할 때 `robo-central.sh` 가 CRLF 로
> 나오고, shebang 이 `bash\r` 이 되어 **리눅스에서 통째로 안 돈다.**
> 2026-10-29 에 실제로 그렇게 올라갔다 — 새로 clone 해 첫 줄을 찍어 보고 잡았다.
>
> **굽기에는 CR 게이트가 있는데(`release.central_script_crlf`) 깃으로 전달하는
> 길은 그 게이트를 지나지 않는다.** 그래서 저장소 쪽에 규칙을 넣었다.
> 올린 뒤에는 **새로 clone 해서 첫 줄을 한 번 본다.**
>
> ```bash
> git clone --branch delivery/<릴리스ID> --depth 1 <url> /tmp/chk
> head -1 /tmp/chk/delivery/<릴리스ID>/central-server/robo-central.sh | od -c | head -2
> ```

## 3. 자산을 올린다

```text
저장소 → Releases → Draft a new release
  태그   릴리스 id 를 그대로 쓴다 (받는 쪽이 그 이름으로 찾는다)
  설명   _delivery\<릴리스ID>\repo\README-전달.md 를 붙인다
  자산   assets\ 폴더의 조각을 끌어다 놓는다 (한 파일 2 GiB 미만)
```

`gh` 로 하면 한 줄이다. ⚠ `gh auth login` 은 사람이 한다.

```powershell
$REL = "<릴리스ID>"
$WS  = "C:\Users\YSW\Desktop\robo-workspace"
gh release create $REL (Get-ChildItem "$WS\_delivery\$REL\assets").FullName `
  --repo uengine-oss/robo-workspace `
  --title $REL --notes-file "$WS\_delivery\$REL\repo\README-전달.md"
```

> ⚠ **별표를 큰따옴표 안에 적지 않는다.** `"...\assets\*"` 는 PowerShell 이
> 풀어 주지 않고 `gh` 도 풀지 않아서 **별표가 글자 그대로** 넘어가고
> *"file does not exist"* 로 끝난다 (2026-10-29 에 인자를 찍어 확인했다).
> 위처럼 `(Get-ChildItem ...).FullName` 으로 **풀어서** 넘긴다.
> 자산이 한 파일뿐일 때도 같다 — 경로를 그대로 적는다.

> ⚠⚠ **`uengine-oss/robo-workspace` 는 공개 저장소다.** 올리면 누구나 받는다.
> 무엇이 드러나는지 재 봤다(2026-10-29):
>
> ```text
> 자격·비밀        **없다** — 네 스냅샷에 자격증명 0건, withheld 3개는 빠져 있다
> 고객 소스        authority 이미지의 templates/template-poscodx 69파일 —
>                 **이미 공개 저장소**다(github.com/msa-ez/template-poscodx)
> 사내 호스트 이름   analyzer 의 llm/configs/pgpt.yaml → aigpt.posco.net ·
>                 taigpt.posco.net. 설치본 스냅샷에도 같은 주소가 있다
> ⇒ 새로 드러나는 것은 **사내 AI 게이트웨이 호스트 이름 둘**이다
> ```
>
> 공개하지 않기로 하면 길은 둘이다.
> ```text
> 비공개 저장소를 따로 둔다   그쪽 Releases 에 올린다(같은 방법)
> 사내 경로로 보낸다         파일 서버 · 사내 Git · 사내 artifact 저장소
>                         (조각과 ASSETS.sha256 은 그대로 쓸 수 있다)
> ```

## 4. 받는 쪽 — 한 폴더로 되돌린다

`repo\README-전달.md` 에 **그 판의 실제 파일 이름으로** 같은 내용이 있다. 요점만:

```bash
# ① 가지를 받는다
git clone --branch delivery/<릴리스ID> --depth 1 \
  https://github.com/uengine-oss/robo-workspace.git
cd robo-workspace/delivery/<릴리스ID>

# ② 자산을 같은 폴더에 내려받는다
gh release download <릴리스ID> --repo uengine-oss/robo-workspace --dir .

# ③ ⚠ 온전한지 **먼저** 본다
sha256sum -c ASSETS.sha256

# ④ 합친다
cat <릴리스ID>.zip.part* > <릴리스ID>.zip

# ⑤ 푼다 — ⚠ **리눅스에서 `tar -xf <zip>` 은 안 된다**
unzip -q <릴리스ID>.zip
#   GNU tar 는 zip 을 못 읽어 "This does not look like a tar archive" 가 난다(실측).
#   unzip 이 없으면  python3 -m zipfile -e <릴리스ID>.zip .
#   윈도우는 `tar -xf` 가 된다 — 들어 있는 tar.exe 가 bsdtar 다

# ⑥ ⚠ 푼 뒤 **다시 대조한다** — 앱이 보는 값과 같은 값이다
cd <릴리스ID> && sha256sum -c SHA256SUMS
```

**여덟 줄 모두 `OK`** 여야 한다. ✔ 이 절차를 **끝까지 한 번 밟아 봤다**
(2026-10-29) — 조각 둘 → 합침 1.91 GiB → 풀기 → 파일 32개 → SHA256SUMS 여덟 줄 OK.

그다음은 가이드 그대로다.

```text
DB 서버(리눅스)   central-server/robo-central.sh 의 [고치는 곳] 둘을 채워 돌린다
                  → 관리자-DB올리기.md
사용자 PC(윈도우) robo-env.ps1 의 [고치는 곳] 을 채워 돌린 뒤 설치본을 깐다
                  → 사용자-설치-가이드.md
```

# 2차선 — 레지스트리로 **이미지**를 보낸다

tar 를 아예 안 보내는 길이다. 되는 이유는 앱과 서버가 **이미지가 이미 있으면
적재를 건너뛰기** 때문이다.

```text
앱       `ensureImages()` 가 열 장의 image ID 를 매니페스트 `imageIds` 와 대조해
         다 맞으면 `docker.images.reused` 로 **tar 를 읽지 않는다**
DB 서버   `robo-central.sh` 가 세 장(graphDb·graphBolt·authority)을 같은 방식으로
         보고 `docker load` 를 건너뛴다
이득      레이어를 나눠 쓰므로 **다음 판은 바뀐 레이어만** 간다.
         2 GiB 벽도, 조각내기도, 1.9 GiB 재전송도 사라진다
```

```powershell
# 보내는 쪽
docker login ghcr.io          # ⚠ **사람이 직접** 한다
pwsh -File scripts\release-images-registry.ps1 -Push `
  -ReleaseDir <릴리스폴더> -Registry ghcr.io/uengine-oss

# 받는 쪽 (윈도우)
pwsh -File release-images-registry.ps1 -Pull `
  -ReleaseDir <받은폴더> -Registry ghcr.io/uengine-oss

# 받는 쪽 (리눅스) — 돌릴 줄만 받아서 쓴다
pwsh -File release-images-registry.ps1 -Pull -Print `
  -ReleaseDir <폴더> -Registry ghcr.io/uengine-oss
```

> ⚠ 받는 쪽은 pull 한 뒤 **원래 이름으로 되태그해야** 한다
> (`ghcr.io/uengine-oss/ontological-db:<id>` → `uengine/ontological-db:<id>`).
> 앱이 보는 이름은 원래 이름이다. 스크립트가 해 주고, `-Print` 도 그 줄을 낸다.

> ⚠ **아직 통과시켜 보지 못한 단계가 하나 있다**: push·pull 을 거친 뒤 image ID 가
> **그대로인지**. 태그는 포인터라 유지돼야 하지만 buildkit·manifest list 가 끼면
> 달라질 수 있다. 스크립트가 pull 뒤에 매니페스트와 대조하고 **다르면 멈춘다** —
> 거기서 걸리면 **1차선(zip)으로 돌아간다.**

> ⚠ 현장 방화벽이 레지스트리를 막고 있을 수 있다. 그때도 1차선으로 돌아간다.

## 정리 — 끝난 뒤

```text
_delivery\<릴리스ID>\assets\   1.9 GiB 다. 올린 뒤에는 지운다
                              (다시 필요하면 스크립트를 다시 돌린다)
worktree                      git worktree remove 로 치운다 —
                              남겨 두면 다음에 가지를 바꿀 때 걸린다
delivery/<릴리스ID> 가지        남겨 둔다. "고객이 받은 판" 의 기록이다
```

> 디스크가 모자라면 **vhdx 수술보다 싼 것부터** — 옛 릴리스 폴더(판당 약 2GB)와
> 이름 지정 `docker rmi` 다. ⚠ `docker volume prune` · `docker system prune -a`
> 는 쓰지 않는다(중앙 그래프 DB 가 볼륨에 있다).

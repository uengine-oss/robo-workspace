# 사용자 설치 가이드 — **내 PC 에 깔고 팀 설계를 함께 봅니다**

> **전제**: 릴리스 폴더 `0.1.0-w…-rint-none` (이름은 판마다 다릅니다) 를 받았고,
> 관리자에게서 접속값 파일
> `pc-central-setup.ps1` 을 받았거나 받을 예정입니다.
>
> **DB 를 세우는 일은 여기 없습니다.** 그건 관리자가 한 번만 하고,
> `관리자-DB올리기.md` 에 있습니다. 이 문서는 **내 PC** 만 다룹니다.

## 이 가이드가 내 PC 에 남기는 것 — 한 장

| 어디에 | 무엇이 | 얼마나 |
|---|---|---|
| `%LOCALAPPDATA%\Programs\Robo-Architect\` | 앱 본체 + 번들 Python | 설치본 |
| 바탕화면 · 시작 메뉴 | 바로가기 | |
| `%APPDATA%\robo-architect-desktop\runtime\` | `robo-images.tar`(내가 복사) · `docker-state.json` | 1.82 GiB |
| `%APPDATA%\robo-architect-desktop\secrets\` | 앱이 만든 비밀 (암호화) | |
| `%APPDATA%\robo-architect-desktop\logs\` | `desktop-<날짜>.log` | |
| Windows 환경변수 | **열일곱** — AI 키 5 · 시험 로그인 6 · 접속값 5 · facade 1 | |
| Docker | 이미지 10 · 네트워크 1 · 볼륨 1 · **컨테이너 7** | 1.95GB |
| 중앙 DB | 첫 로그인 때 **내 사번 한 줄** | |

소스 저장소는 **하나도 받지 않는다.** 이 절차는 **인터넷을 쓰지 않는다** —
받은 파일만으로 끝난다(AI 키 확인 한 단계만 예외, §3).

## 순서대로 — **이것만 하면 됩니다**

각 줄의 `#` 주석이 그 단계의 설명입니다. 왜 그런지는 아래 각 절에 있습니다.
전부 **PowerShell** 입니다(관리자 권한은 필요 없습니다).

```powershell
# ① 받은 릴리스 폴더로 갑니다 (파일 넷이 같은 폴더에 있어야 합니다)
cd <릴리스 폴더>

# ② 지난 설치가 남긴 환경변수를 지웁니다 — 남아 있으면 새 설치를 조용히 망칩니다
powershell -ExecutionPolicy Bypass -File .\robo-env.ps1 -Clear

# ③ **로그아웃·재로그인** 합니다 — Windows 는 로그인할 때 환경변수를 읽습니다

# ④ 파일이 옮기는 중에 깨지지 않았는지 봅니다 — 위아래 값이 짝을 이뤄야 합니다
Get-Content .\SHA256SUMS
Get-ChildItem .\Robo-Architect-Setup-*.exe, .\robo-images.tar, .\robo-env.ps1 |
  ForEach-Object { "{0}  {1}" -f (Get-FileHash -Algorithm SHA256 $_).Hash.ToLower(), $_.Name }

# ⑤ Docker 가 도는지 봅니다
docker info --format "{{.ServerVersion}}"

# ⑥ 환경값 파일 하나를 채웁니다 — AI 키 하나 + 관리자가 준 접속값
#    ⚠ **UTF-8(BOM)** 으로 저장합니다. BOM 이 없으면 한글 주석이 깨져 구문 오류가 납니다
notepad .\robo-env.ps1
powershell -ExecutionPolicy Bypass -File .\robo-env.ps1

# ⑦ **로그아웃·재로그인**, 그리고 ⚠ 이 파일을 **지웁니다**(비밀이 평문입니다)
Remove-Item .\robo-env.ps1

# ⑧ 설치본을 깝니다 — ⚠ 마지막 화면의 **"Robo-Architect 실행" 체크를 끕니다**
.\Robo-Architect-Setup-*.exe

# ⑨ 부품 묶음을 옮깁니다 (1.8GB 복사 · 1~3분)
$dst = "$env:APPDATA\robo-architect-desktop\runtime"
New-Item -ItemType Directory -Force -Path $dst | Out-Null
Copy-Item .\robo-images.tar -Destination $dst -Force

# ⑩ 바탕화면 아이콘으로 앱을 켭니다 — 처음은 몇 분 걸립니다

# ⑪ 제대로 떴는지 봅니다 — **일곱 줄** 모두 healthy 여야 합니다
docker ps --filter "label=com.docker.compose.project=robo-architect-desktop" `
  --format "{{.Names}}  {{.Status}}"
```

안 되면 **§9 안 될 때**를 봅니다.

## 0. 이 문서를 끝까지 따라가면 무엇이 되나

**시작하기 전에 이미 손에 있어야 하는 것** — 만든 사람에게서 USB·파일 서버로
건네받습니다. **이 문서의 어느 명령도 인터넷에서 무언가를 내려받지 않습니다.**

```
Robo-Architect-Setup-<버전>.exe    약 106 MB (판마다 다릅니다)
robo-images.tar                    1.95 GB
SHA256SUMS                         몇 줄
```

```
  절    하는 일                    →   그 결과 생기는 것
──────────────────────────────────────────────────────────────────────
  §1    받은 파일 해시 대조             안 깨졌다는 확인만 (설치 안 됨)
  §2    Docker Desktop 켜기            서비스를 돌릴 엔진 준비
  §3    비밀값 8개 넣기                 앱이 켜질 수 있는 상태
  §4    설치 파일 실행                  시작 메뉴에 프로그램
  §5    tar 를 지정 폴더로 복사          앱이 부품을 찾을 수 있게 됨
  §6    앱 실행                        서비스 **일곱** 기동 (첫 회 4~5분)
  §7    로그인                         화면 사용 가능
```

### 전체 소요 시간

```
§1~§5  파일 확인·설치·설정      10~15분   (대부분 1.95GB 복사 시간)
§6     첫 실행                   4~5분    (부품 묶음 적재. 두 번째부터는 1분)
§7~§8  로그인·확인                5분
```

### 미리 알아 두면 헷갈리지 않는 것 셋

**① 왜 파일이 두 개인가.** 설치 파일 안에는 **앱 껍데기만** 있습니다. 실제 일을
하는 서비스들은 `robo-images.tar` 안에 들어 있습니다(이미지 **열 개**, 그중 이 PC 가
띄우는 것은 **일곱**). 1.95GB 를 설치 파일에
넣으면 설치 파일 생성기가 감당하지 못해서 옆에 따로 둡니다.

**② 왜 Docker 가 필요한가.** 그 서비스를 돌려 주는 엔진입니다. 앱이 켜지면
**앱이 알아서 일곱**을 띄웁니다 — 사용자가 Docker 명령을 칠 일은 없습니다.
**데이터베이스는 이 PC 에 깔지 않습니다** — 관리자가 한 곳에 세워 둔 것을 함께 씁니다.

**③ 소스 코드는 필요 없습니다.** 이 문서 1부에는 git·Node·Python 이 한 번도
나오지 않습니다. 그것들은 2부(설치 파일을 **만드는** 쪽)에만 필요합니다.

```
설치되고 나면 이렇게 돕니다

  Windows 프로그램        앱 화면 + 백엔드(설치 폴더 안의 파이썬)
  Docker 컨테이너 일곱     관문 1 · 분석 1 · 데이터 2 · 파싱 1 · 문서변환 1 · 화면생성 1
  저장소(DB)              **이 PC 에 없습니다** — 관리자가 세운 서버에 하나
```

## 0-A. 시작 전 — 이전 설치가 남긴 환경변수를 지웁니다

> ⚠ **왜 `powershell -ExecutionPolicy Bypass -File` 로 부르나.** Windows 의
> 기본 실행 정책은 `Restricted` 라서, `.\robo-env.ps1` 처럼 바로 부르면
> *"이 시스템에서 스크립트를 실행할 수 없으므로 … 로드할 수 없습니다"* 로
> **아예 안 돕니다**(2026-10-29 실측). 아래 형태는 그 PC 의 정책을 **바꾸지
> 않고** 이 한 번만 넘깁니다 — `Set-ExecutionPolicy` 로 PC 설정을 바꾸지
> 않아도 됩니다.


> **왜**: 앱을 지워도, `%APPDATA%` 를 비워도, Docker 를 비워도 **Windows 환경변수는
> 남습니다.** 그중 `ROBO_GRAPH_MODE=central` 이 남아 있으면 앱은 로컬 DB 를 띄우지 않고
> **이미 없어진 서버를 기다립니다.**
>
> **결과**: 아래 §3 이 넣는 값만 남아, 지금 설치하는 구성 그대로 돕니다.

**이 PC 에 Robo Architect 를 처음 설치한다면 건너뜁니다.** 전에 깔았던 PC,
또는 구성을 바꾸는 PC 라면 반드시 합니다.

> `robo-env.ps1` 은 **릴리스 폴더 안**에 있습니다. §1 에서 파일을 모아 둘
> 폴더(예: `C:\robo-install`)에 **함께 복사해 두고** 그 폴더에서 돌립니다.
> (설치를 마치면 설치 폴더의 `resources\runtime\` 에도 같은 파일이 있습니다.)

```powershell
cd <robo-env.ps1 을 둔 폴더>
powershell -ExecutionPolicy Bypass -File .\robo-env.ps1 -Clear
```

`지움` 이라고 쳐야 지웁니다. 끝나면 **전부 `★ 없음`** 으로 나옵니다.

### ⚠ AI 키는 지우면 되돌릴 수 없습니다

발급받은 키를 따로 들고 있지 않다면 **먼저 빼둡니다.** 화면에 찍지 않고 파일로
보냅니다. `-Clear` 가 실행 전에 이 명령을 다시 알려 줍니다.

```powershell
[Environment]::GetEnvironmentVariable('OPENAI_API_KEY','User') | Set-Content -NoNewline "$env:USERPROFILE\Desktop\ai-key.txt"
```

§3 에서 그 값을 넣은 뒤 **이 파일을 지우십시오.**

### 지운 뒤 **로그아웃·재로그인**합니다

> 환경변수는 **새로 시작한 프로세스부터** 적용됩니다. 탐색기까지 새로 떠야 아이콘으로
> 띄운 앱이 바뀐 값을 봅니다 — 그래서 로그아웃·재로그인을 합니다.

[§0-A 가 남기는 것]

## 1. 전달받은 파일이 온전한지 확인합니다

> **왜**: 1.95GB 를 USB·네트워크로 옮기면 조용히 깨질 수 있습니다. 그대로 설치하면
> **한참 뒤 엉뚱한 곳에서** 실패합니다.
>
> **결과**: 파일이 온전하다는 확인뿐입니다. **아무것도 내려받지 않고, 아무것도
> 설치되지 않습니다.**

### ⚠ 이 절에서 하지 않는 것

| | |
|---|---|
| 인터넷에서 내려받기 | ❌ **안 합니다.** 받은 파일만 대조합니다 |
| 소스 코드 클론 | ❌ **안 합니다.** `git` 은 1부에 한 번도 안 나옵니다 |
| 설치 | ❌ 그건 §4 입니다 |

**파일 세 개는 이미 손에 있어야 합니다.** 이 절은 그것들이 옮겨 오는 동안
깨지지 않았는지 **대조만** 합니다.

### 전달받을 파일 — **릴리스 폴더 안에 다 있습니다**

| 파일 | 크기 | 무엇 |
|---|---|---|
| `Robo-Architect-Setup-<버전>.exe` | 약 106 MB | 설치 파일 |
| `robo-images.tar` | 약 1.95 GB (1.82 GiB) | 프로그램이 쓰는 부품 묶음 |
| `SHA256SUMS` | 몇 줄 | 위 둘이 깨지지 않았는지 확인하는 값 |
| `robo-env.ps1` | 250여 줄 | **환경값을 넣는 파일** (§3) — 릴리스 폴더에 함께 있습니다 |

**어디서 받나** — 설치 파일을 만든 사람에게서 받습니다(USB·파일 서버·사내 공유).
**넷 모두 릴리스 폴더 안에 들어 있습니다** — 그 폴더를 통째로 받으시면 됩니다.
`SHA256SUMS` 가 `robo-env.ps1` 까지 묶고 있어 온전한지 함께 확인됩니다.

> **직접 구우신 분이라면** 이미 갖고 계십니다. 2부 §15 를 끝내면
> `robo-workspace\_releases\<버전>\` 안에 그대로 있습니다. 그 폴더에서 아래를
> 진행하시면 됩니다.
>
> ```
> _releases\0.1.0-w…\
>   Robo-Architect-Setup-0.1.0-w….exe
>   robo-images.tar
>   SHA256SUMS
>   robo-env.ps1               ← 환경값을 넣는 파일 (§0-A·§3)
>   runtime-manifest.json      ← 이건 전달 안 해도 됩니다(설치 파일 안에 있음)
> ```

**어디에 두나** — 아무 폴더나 괜찮습니다. **넷을 같은 폴더에** 두기만 하면 됩니다.
이 문서는 `C:\robo-install` 을 예로 씁니다.

```
C:\robo-install\
  Robo-Architect-Setup-0.1.0-w….exe
  robo-images.tar
  SHA256SUMS
  robo-env.ps1                     ← 릴리스 폴더에 함께 들어 있습니다 (§0-A·§3)
```

`robo-images.tar` 가 설치 파일 **안에 들어 있지 않은 이유**: 1.95GB 를 설치 파일에
넣으면 설치 파일을 만드는 프로그램이 감당하지 못합니다. 그래서 옆에 따로 둡니다.

### 옮기는 중에 깨지지 않았는지 확인합니다

**① PowerShell 을 엽니다** — 시작 메뉴에서 `powershell` 을 검색해 실행합니다.
관리자 권한은 필요 없습니다.

**② 파일을 둔 폴더로 이동합니다** — 경로를 자기 것으로 바꿔서 붙여 넣습니다.

```powershell
cd C:\robo-install
```

**이렇게 나와야 합니다**: 프롬프트가 `PS C:\robo-install>` 로 바뀝니다.
`경로를 찾을 수 없습니다` 가 나오면 폴더 이름을 다시 확인하세요.

**③ 아래를 통째로 복사해 붙입니다.**

이 명령이 하는 일은 딱 둘입니다 — **내려받는 동작은 없습니다.**

```
첫 줄   SHA256SUMS 파일에 적힌 값을 그냥 화면에 보여준다
둘째 줄 내 폴더의 파일 둘을 실제로 읽어 같은 방식으로 값을 계산한다
        → 사람이 눈으로 위아래를 비교한다
```

```powershell
Get-Content .\SHA256SUMS
Get-ChildItem .\Robo-Architect-Setup-*.exe, .\robo-images.tar, .\robo-env.ps1 |
  ForEach-Object { "{0}  {1}" -f (Get-FileHash -Algorithm SHA256 $_).Hash.ToLower(), $_.Name }
```

**이렇게 나와야 합니다**: **내가 가진 세 파일**의 값이 위아래에서 짝을 이룹니다.

```
a65ef2d2...b678  Robo-Architect-Setup-0.1.0-....exe     ← SHA256SUMS 에 적힌 값
ebd6e5f0...fd15  robo-images.tar
f64ffa08...      central-server/compose.yml             ↑ 관리자용 파일 다섯도
19fe1e10...      central-server/central-authority.env.example   같이 적혀 있습니다
5c17ae63...      central-server/README.md
8f21c0b4...      central-server/robo-central.sh
d257e794...      central-server/runtime-manifest.json
6b3a933a...      robo-env.ps1
a65ef2d2...b678  Robo-Architect-Setup-0.1.0-....exe     ← 실제 파일에서 계산한 값
ebd6e5f0...fd15  robo-images.tar
6b3a933a...      robo-env.ps1
```

> **윗쪽이 여덟 줄인 것이 정상입니다.** `central-server/` 다섯은 **관리자**가
> 쓰는 파일이라 이 PC 에서는 쓰지 않습니다. 내가 볼 것은 **위아래에 두 번
> 나오는 그 세 줄**입니다.
>
> ⚠ 값은 **판마다 다릅니다.** 위는 모양을 보여 주는 예일 뿐입니다 — 내 폴더의
> `SHA256SUMS` 에 적힌 값과 아래에서 계산한 값이 **서로** 같은지만 보시면 됩니다.

값이 다르면 **옮기는 중에 파일이 깨진 것**입니다. 다시 받으세요. 그대로 설치하면
나중에 엉뚱한 곳에서 실패합니다.

## 3. 환경값 파일 하나를 채워 돌립니다

> **왜**: 설치 파일 안에는 비밀번호·AI 키가 **하나도 없습니다.** 파일이 누구 손에
> 들어가도 비밀이 새지 않게 하려는 것입니다. 대신 "무엇이 필요한지 이름만" 들어
> 있고, 값은 설치하는 사람이 Windows 에 넣습니다.
>
> **결과**: 앱이 켜지고, 팀 DB 에 붙고, 분석까지 되는 상태가 됩니다.
>
> **한 번만** 하면 됩니다. 앱을 다시 깔아도 이 값은 남습니다.

### 쓰는 법 — 세 줄

```powershell
# 1) robo-env.ps1 을 메모장으로 열어 [고치는 곳] 만 채웁니다
# 2) 돌립니다
powershell -ExecutionPolicy Bypass -File .\robo-env.ps1
# 3) **로그아웃·재로그인** 하고, ⚠ **이 파일을 지웁니다**
```

⚠ **이 파일은 UTF-8(BOM) 로 저장해야 합니다.** 메모장은 "UTF-8(BOM)" 으로 저장하면
됩니다. BOM 이 없으면 Windows PowerShell 이 한글 주석을 깨뜨려 **구문 오류**가 납니다.

### 무엇을 채우나 — **여섯 자리** (+ 포트 둘은 보통 비웁니다)

| 이 파일의 변수 | 무엇 | 어디서 |
|---|---|---|
| `$AI_KEY` | AI 키 **하나** | 발급받은 키. 아래 다섯 이름에 같은 값이 들어갑니다 |
| `$GRAPH_HOST` | 중앙 DB 서버의 **사내망 IP** | **관리자가 줍니다** |
| `$GRAPH_PASSWORD` | DB 비밀번호 | **관리자가 줍니다** |
| `$ROLE_SECRET` | 프로젝트 권한용 | **관리자가 줍니다** ★ 모든 PC 가 같은 값 |
| `$JWT_SECRET` | 로그인 유지용 | **관리자가 줍니다** |
| `$DEV_*` | 시험 로그인 | 그대로 둬도 됩니다 (`admin`/`admin`) |
| `$GRAPH_PG_PORT`·`$GRAPH_BOLT_PORT` | DB 포트 | **보통 비웁니다.** 기본이 5432·7687 입니다 |
| `$IMAGE_TAR` | 부품 묶음 자리 | **보통 비웁니다.** 적으면 §5 의 복사를 건너뜁니다 |

> **포트 두 자리는 왜 있나.** 중앙 DB 를 올린 서버에서 **다른 프로그램이 5432 를
> 이미 쓰고 있으면** 관리자가 옮겨 열었을 수 있습니다(사내망의 msa-ez 가 그렇습니다).
> 그때만 관리자가 알려 준 숫자를 적습니다. **비워 두면 기본값을 씁니다.**

> **관리자가 이 PC 에 DB 를 올렸다면** 접속값 넷은 이미 들어가 있습니다.
> 그 자리를 **비워 두면 이 스크립트가 건드리지 않습니다** — 지우지 않습니다.

> ⚠ **`$ROLE_SECRET` 은 한 번 정하면 바꾸지 마세요.** 바꾸면 이미 만든
> 프로젝트에 접근하지 못합니다. 사용자 한 명 = DB 계정 하나이고, 그 비밀번호를
> **이 값과 사번으로 계산해 내기** 때문입니다(저장하지 않습니다).

> ⚠ **`$ROLE_SECRET`·`$JWT_SECRET` 을 직접 만들지 마십시오.** 관리자가 정한
> **공용 값**입니다. 난수로 만들면 서버와 어긋나 프로젝트를 열 수 없습니다.

### 스크립트가 알아서 하는 것

```text
AI 키 다섯 이름에 같은 값     서비스마다 읽는 이름이 달라서입니다
PDF2BPMN_FACADE_KEY 난수     이 PC 것. **이미 있으면 그대로 둡니다**
                            (바꾸면 떠 있는 컨테이너와 어긋납니다)
ROBO_GRAPH_MODE=central     $GRAPH_HOST 를 채우면 자동으로 들어갑니다
시험 로그인 여섯 이름          $DEV_LOGIN = $false 면 **여섯을 모두 지웁니다**
주소 규칙 검사               localhost · 127.* · host.docker.internal ·
                            WSL 주소(172.16~31.*)면 **넣지 않고 멈춥니다**
```

> 마지막 줄이 중요합니다. `ROBO_GRAPH_HOST` 는 이 PC 의 컨테이너 일곱에도 그대로
> 들어가므로, 컨테이너 안에서 `localhost` 는 자기 자신이 됩니다. 잘못 넣으면
> 증상이 **"fabric is unhealthy"** 로 엉뚱하게 나와 원인을 찾기 어렵습니다.

### ⚠ "기동을 막는 것" 과 "없으면 기능이 실패하는 것" 은 다릅니다

이 둘을 한 덩어리로 보면 **앱은 떴는데 분석이 조용히 실패하는** 상태에 빠집니다.

```text
① 기동을 막는다   매니페스트의 `credentialNames` 에 적힌 이름.
                 하나라도 비면 창이 **안 뜨고** `runtime.credentials_missing`
                 으로 멈춘다
                 ⚠ **개수는 릴리스마다 다르다** — 굽는 기계에 값이 들어 있던
                   이름만 적히기 때문이다. 이 판(10-22)은 **셋**이다
② 없으면 기능이 실패한다   앱은 **멀쩡히 뜬다**. 그래서 더 늦게 드러난다
                 AUTH_ROLE_SECRET 이 비면   → 프로젝트를 **열 수 없다**
                 AI 키 별칭이 비면          → 분석·탐색이 **그때** 실패한다
                 PDF2BPMN_FACADE_KEY 가 비면 → 문서 변환이 실패한다
```

### 확인 — 값은 보지 않고 길이만 봅니다

```powershell
powershell -ExecutionPolicy Bypass -File .\robo-env.ps1 -Check
```

**아무것도 바꾸지 않습니다.** 지금 상태를 보여 주고, **설치본을 깐 뒤라면**
매니페스트를 읽어 *이 릴리스가 기동에 요구하는 이름*이 다 찼는지도 같이 셉니다.

> 값 자체를 화면에 띄우지 마세요. 화면 캡처·채팅·문서에 남으면 그 키는 폐기해야
> 합니다. 이 스크립트는 **길이만** 찍습니다.

### AI 키가 **살아 있는지**도 확인합니다

**"있음" 은 "맞다" 가 아닙니다.** 폐기되거나 오타가 난 키도 "있음" 으로 나옵니다.
실제로 한 번 불러 봐야 압니다. 아래는 값을 찍지 않고 **응답 코드만** 봅니다.

```powershell
foreach ($k in 'OPENAI_API_KEY','LLM_API_KEY','ROBO_LLM_API_KEY',
               'ROBO_EMBED_API_KEY','ROBO_SEARCH_LLM_API_KEY') {
  $v = [Environment]::GetEnvironmentVariable($k,'User')
  if (-not $v) { "{0,-26} ★ 없음" -f $k; continue }
  try {
    $r = Invoke-WebRequest -Uri 'https://api.openai.com/v1/embeddings' -Method Post `
      -Headers @{ Authorization = "Bearer $v" } -ContentType 'application/json' `
      -Body '{"model":"text-embedding-3-small","input":"x"}' `
      -TimeoutSec 25 -UseBasicParsing
    "{0,-26} OK ({1})" -f $k, $r.StatusCode
  } catch {
    "{0,-26} ★ 실패 ({1})" -f $k, $_.Exception.Response.StatusCode.value__
  }
}
```

**다섯 줄 모두 `OK (200)`** 이어야 합니다.

| 나온 것 | 뜻 | 할 일 |
|---|---|---|
| `★ 실패 (401)` | 키가 틀렸거나 **폐기됐습니다** | 새 키를 받아 `$AI_KEY` 를 고치고 다시 돌립니다 |
| `★ 실패 (429)` | 키는 맞고 사용량이 찼습니다 | 결제·한도를 확인합니다 |
| 전부 멈춤 | 이 망에서 OpenAI 로 못 나갑니다 | 프록시·방화벽 담당자에게 문의. msa-ez 가 쓰는 길과 같은지 확인 |

> **⚠ 이 확인은 이 문서에서 유일하게 바깥(api.openai.com)으로 나갑니다.**
> **그 망이 열려 있다고 가정하지 마십시오.** 같은 망의 msa-ez platform 이
> `OPENAI_API_KEY` 를 쓰고 있지만, 그 이미지를 받을 때도 **방화벽을 임시로 열거나
> 관리자가 tar 를 옮겨 `docker load` 로 넣는 식**이었습니다 — 상시로 열려 있다는
> 뜻이 아닙니다.
>
> ```text
> 먼저 담당자에게 묻습니다 — **AI 를 부르는 길이 무엇입니까**
>   ① 바깥으로 바로 나간다        → 이 확인을 그대로 합니다
>   ② 사내 게이트웨이를 거친다     → 그 주소로 바꿔서 확인합니다
>                                  (msa-ez 도 같은 자리에 `OPENAI_BASE_URL` 을 둡니다)
>   ③ 아예 못 나간다              → 이 단계를 건너뜁니다. **설치는 됩니다** —
>                                  다만 분석·탐색이 그때 실패하므로 ②를 먼저 정합니다
> ```

### 키를 바꿀 때 (폐기·만료·교체)

키가 외부에 노출되면 OpenAI 가 **스스로 폐기합니다.** 그러면 앱은 켜지지만
분석·탐색이 전부 실패합니다.

```text
① `$AI_KEY` 만 새 값으로 고칩니다 — 접속값 넷은 비워 두면 안 건드립니다
② `.\robo-env.ps1` 을 다시 돌립니다 (다섯 이름이 **함께** 바뀝니다)
③ **앱을 완전히 끕니다** — 환경변수는 **켤 때** 읽습니다.
   떠 있는 앱과 컨테이너는 옛 값을 쥐고 있습니다
④ 위 "살아 있는지" 를 다시 하고, 다섯 줄 `OK (200)` 을 보고 나서 켭니다
```

⚠ `AUTH_ROLE_SECRET` 은 **AI 키와 무관합니다.** 그것을 바꾸면 **기존 프로젝트에
접근하지 못합니다.**

평문으로 들어 있습니다 — 넣었으면 지웁니다.

`.\robo-images.tar` 는 **§1 에서 이동한 폴더** 기준입니다. 첫 줄의 `cd` 를 자기
경로로 바꾸세요.

```powershell
cd C:\robo-install
$dst = "$env:APPDATA\robo-architect-desktop\runtime"
New-Item -ItemType Directory -Force -Path $dst | Out-Null
Copy-Item .\robo-images.tar -Destination $dst -Force
Get-Item "$dst\robo-images.tar" | Select-Object @{n='GB';e={[math]::Round($_.Length/1GB,2)}}
```

**이렇게 나와야 합니다**: `1.8` 정도(판마다 조금 다릅니다). 1.95GB 복사라 **1~3분** 걸립니다.

> `$dst` 의 `$env:APPDATA` 는 **자동으로 자기 계정 경로**가 됩니다. 손으로 바꿀
> 필요 없습니다.

### 복사하지 않는 길 — 공유 폴더·USB 의 tar 를 그대로 쓸 때

tar 가 상시 열려 있는 공유 폴더에 있다면 **1.95GB 를 복사하지 않아도** 됩니다.
§3 의 `robo-env.ps1` 에서 `$IMAGE_TAR` 에 그 **절대 경로**를 적고 돌리면 됩니다
(그러면 위 복사 블록을 건너뜁니다).

```text
$IMAGE_TAR = '\\파일서버\배포\robo-images.tar'      ← 예
```

| | 복사한다 (기본) | 경로만 준다 |
|---|---|---|
| 설치 시간 | 1~3분 더 | 바로 |
| 디스크 | 1.95GB 더 씀 | 안 씀 |
| 나중에 | **이 PC 만으로** 이미지를 다시 올릴 수 있다 | 그 경로가 살아 있어야 한다 |

> ⚠ **tar 는 첫 기동에만 읽습니다.** 그 뒤로는 안 봅니다 — 그래서 경로를 줘도
> 평소에는 아무 차이가 없습니다. 차이가 나는 때는 **이미지를 다시 올려야 할 때**
> (앱을 다시 깔거나 Docker 를 비운 뒤)입니다. 그때 그 공유 폴더가 없으면
> 멈춥니다.

> ⚠ 경로에 오타가 있으면 앱은 **조용히 다음 자리로 넘어갑니다.** 그래서
> `robo-env.ps1` 이 **넣기 전에 그 파일이 실제로 있는지 봅니다** — 없으면
> 넣지 않고 멈춥니다.

**20여 대에 USB 로 돌리는 상황이면 복사가 맞습니다.** 공유 폴더가 상시 열려
있는 환경이면 경로를 주는 쪽이 훨씬 낫습니다.

## 7. 로그인합니다

현장에서는 **POSCO SSO** 로 로그인합니다. 사내망 밖에서는 SSO 서버에 닿지 않으므로,
시험용 계정으로 확인합니다.

### 시험 관리자 `admin` / `admin`

**§3 에서 이미 넣었습니다.** 여기서는 그 값이 무엇을 뜻하는지만 봅니다.

```text
AUTH_DEV_LOGIN_ID / PASSWORD   로그인 화면에 칠 아이디·비밀번호
AUTH_DEV_LOGIN_EMPNO           **사용자 표의 uid**. 관리자가 `grant --employee-no` 에
                               쓴 값과 **같아야** 한다 — 기본은 `DEV-ADMIN`
AUTH_DEV_LOGIN_ACCOUNTS        추가 계정들. **이 이름이 비면 앱이 기동하지 않는다**
```

아무것도 안 넣으면 기본이 `test` / `test`(사번 `DEV-TEST`)입니다. §3 처럼 넣으면
**그 자리가 `admin` / `admin` 으로 바뀝니다** — 둘이 같이 생기지 않습니다.

### 일반 사용자 계정도 하나 — 프로젝트 격리를 보려면 **둘이 필요합니다**

```powershell
[Environment]::SetEnvironmentVariable('AUTH_DEV_LOGIN_ACCOUNTS','user1:user1::사용자1:개발','User')
```

`id:비밀번호:사번:이름:부서` 이고 `,` 또는 줄바꿈으로 여럿을 씁니다. **사번 자리를 비우면
`DEV-<아이디>` 가 자동으로 붙습니다** — 위 예는 uid 가 `DEV-USER1` 이 됩니다. 이 계정은
`grant` 를 하지 않으므로 **일반 사용자(member)** 로 들어옵니다. 그게 격리 시험의 요점입니다.

> 같은 아이디가 겹치면 **앞의 것이 이깁니다.** `AUTH_DEV_LOGIN_ACCOUNTS` 에 `admin` 을
> 또 적어도 위 `AUTH_DEV_LOGIN_*` 이 이깁니다 — 오타 하나로 관리자 비밀번호가 조용히
> 바뀌지 않게 해 둔 것입니다.

설정한 뒤 **로그아웃·재로그인**하고 앱을 다시 엽니다. 이 우회 로그인은 **그 PC 에서만**
되고, 다른 PC 에서 같은 주소로 들어오면 거부됩니다(루프백만 허용).

> **납품 상태에서는 이 값을 넣지 마세요.** 아이디·비밀번호만으로 들어오는 문입니다.
> 시험이 끝나면 **여섯 개를 모두** 지웁니다 — `ENABLED` 하나만 지워도 문은 닫히지만,
> 나머지가 남아 있으면 다음 사람이 그걸 보고 다시 켭니다.
>
> ```powershell
> foreach ($n in 'AUTH_DEV_LOGIN_ENABLED','AUTH_DEV_LOGIN_ID','AUTH_DEV_LOGIN_PASSWORD',
>                'AUTH_DEV_LOGIN_EMPNO','AUTH_DEV_LOGIN_NAME','AUTH_DEV_LOGIN_ACCOUNTS',
>                'AUTH_DEV_LOGIN_ALLOW_REMOTE') {
>   [Environment]::SetEnvironmentVariable($n, $null, 'User')
> }
> ```
>
> 그리고 **DB 에 남은 `DEV-ADMIN` 사용자도 지워야 합니다** — 환경변수를 지워도 사용자
> 표의 그 행은 남습니다. 실제 관리자를 `grant` 한 뒤 `revoke` 하십시오(마지막 관리자는
> 지워지지 않으므로 순서가 그렇습니다).

## 8. 잘 설치됐는지 스스로 확인하는 목록

아래를 순서대로 해 보고 **하나라도 다르면** §9 를 봅니다.

| # | 확인할 것 | 이렇게 나와야 합니다 |
|---|---|---|
| 1 | 서비스 상태 | 이 PC 의 컨테이너 **일곱**이 `healthy`. 서버의 DB/Bolt 둘은 내 목록에 없다. 앱 감독 목록은 전부 `ready` |
| 2 | 기다리는 화면 | 백엔드가 뜰 때까지 `인증 설정을 확인하는 중` — **열리지 않는 것이 정상** |
| 3 | 로그인 화면이 뜬다 | 로그인 전에는 아무 내용도 안 보인다 |
| 4 | 로그인이 된다 | **연결·폴더를 묻지 않고** 바로 `Legacy` 탭이 열린다 |

| 7 | 앱을 껐다 켠다 | **만든 프로젝트가 그대로 있다** · **로그인은 다시 한다** |
| 8 | PC 를 재시작한다 | 앱을 열면 그대로 이어진다 |
| 9 | 로그 파일 | `logs\` 에 `desktop-<오늘날짜>.log` 가 있다 |

7번이 중요합니다. **데이터는 남고 세션은 끝나야** 합니다 — 데이터가 사라지면
볼륨 문제이고, 로그인을 안 물으면 세션이 디스크에 남은 것입니다.

2번도 함께 봅니다. 기다리는 동안 화면이 **열려 있으면 안 됩니다** — 인증 강제
여부를 모르는 상태에서 여는 것이 예전에 로그인을 통째로 건너뛰던 결함이었습니다.

### 서비스 ID — 회사 체계의 번호를 붙이려면

회사에 서비스를 식별하는 자기 번호 체계가 있으면 그 값을 붙일 수 있습니다.
안 붙여도 됩니다 — 비워 두면 프로그램이 알아서 번호를 만듭니다.

```text
프로젝트   만들 때 이름 아래 칸에 적습니다
           ⚠ **지금 적지 않으면 나중에 적을 길이 없습니다**
적재        문서를 올리는 창의 `서비스 ID` 칸에 적습니다
           ⚠ **적재마다 새 값**이어야 합니다. 쓴 값은 다시 못 씁니다
```

| 이런 모양 | 안 되는 모양 |
|---|---|
| `ROBO-2026-001` · `HR_LEAVE_01` · `erp.billing.v2` | `연차관리`(한글) · `ROBO 2026`(공백) · `A`(한 자) |

영문·숫자로 시작하고 끝나며, 가운데에 `-` `_` `.` 을 쓸 수 있습니다(2~64자).

> **칸이 안 보이면** 그 프로젝트의 **소유자가 아닙니다.** 서비스 ID 는 프로젝트를
> 만든 사람만 정합니다. 문서를 올리는 일 자체는 편집 권한만 있으면 됩니다 —
> 번호 없이 적재됩니다. 번호가 필요하면 프로젝트를 만든 사람에게 말합니다.

> **이미 쓰고 있는 서비스 ID 입니다** 가 뜨면 그 값을 누군가 이미 썼습니다.
> 대소문자는 구별하지 않습니다 — `ROBO-1` 과 `robo-1` 은 같은 값으로 봅니다.

> **유일성 검사가 아직 없습니다** 가 뜨면 **관리자에게 말합니다.** 서버에서
> 한 번 돌릴 명령이 남아 있다는 뜻입니다(`관리자-DB올리기.md` 의 "새 릴리스로
> 올릴 때"). 그때까지는 서비스 ID 를 비워 두고 만들면 됩니다.


### 데이터베이스 확인은 **내가 하지 않습니다**

데이터베이스는 이 PC 에 없습니다. 속이 비어 있는지는 **관리자가** 세울 때
확인합니다(`관리자-DB올리기.md` 5번). 내 쪽에서 DB 가 제대로인지 보는 방법은
**로그인이 되고 프로젝트 목록이 열리는 것** 하나입니다 — 그게 §7 입니다.

로그인이 `503 AUTH_NOT_INITIALIZED` 로 막히면 **내 PC 문제가 아닙니다.**
관리자에게 "초기화(5번)를 했는지" 물어봅니다.

`plpgsql` 하나만 나오면 **데이터베이스가 준비되지 않은 것**입니다. §9 의 마지막
줄을 보세요.

| 앱은 떴는데 화면이 비어 있다 | 로그인을 안 했다 | 로그인한다 |
| **"프로젝트를 먼저 고르세요"** | 정상이다 | 프로젝트를 만들거나 고른다 |
| 앱이 갑자기 닫힌다 | 옛 빌드(2026-09-28 이전)의 알려진 문제 | 지금 받은 설치본에는 해당 없습니다. 그래도 나면 로그를 주세요 |
| **`safeStorage` 로 시작하는 긴 영어 오류** | 비밀 저장소의 열쇠가 바뀌었다 (재설치·PC 이전) | **데이터는 안 지워졌습니다.** `app-operations.md`(가이드 폴더가 아니라 **그 위 폴더**에 있습니다) 의 백업 절을 보세요 |
| 확장이 `plpgsql` 하나뿐 | 데이터베이스 초기화가 안 됐다 | 옛 빌드(2026-09-28 이전)의 결함입니다. 지금 받은 설치본에는 해당 없습니다 |

#### 부품 하나가 안 떠서 앱이 안 뜰 때

부품들은 **앞의 것이 준비된 뒤에** 뜨도록 묶여 있습니다. 그래서 맨 앞 하나가
못 뜨면 뒤의 것들은 **시작조차 하지 않습니다**(그래서 서비스가 일곱이 아닙니다).

앱을 끄고 **바탕화면 아이콘**으로 다시 켜 보십시오. 대개 그것으로 이어서 뜹니다.
**볼륨을 지우지 않으니 데이터는 그대로입니다.**

> ⚠ 2026-10-27 판부터 **`mindsdb` 가 없습니다.** 예전에는 그 부품이 맨 앞에
> 있어 그것 하나가 못 뜨면 앱이 통째로 안 떴습니다. 지금은 데이터 소스 연결을
> **관리자 서버의 데이터베이스가 직접** 하므로 그 자리가 사라졌습니다.

### 로그 보는 법 — **앱 안에서 먼저**

서비스가 실패로 보이면 그 줄의 **"로그 보기"** 를 누릅니다. 눈에 걸릴 줄만 골라
보여주고(같은 것이 반복되면 묶어서 몇 번인지 적습니다), **"전문 N줄"** 로 전체를
펼칠 수 있습니다. 비밀값은 가려서 나옵니다. **"폴더 열기"** 는 원본 파일 자리입니다.

앱이 아예 안 뜨면 파일을 직접 봅니다.


```powershell
Get-Content "$env:APPDATA\robo-architect-desktop\logs\desktop-$(Get-Date -f yyyy-MM-dd).log" -Tail 30
```

맨 끝 줄에 `"status": "fatal"` 과 그 이유가 적혀 있습니다. 그 문장을 그대로
전달해 주시면 됩니다.

문제 보고 시 함께 주시면 좋은 것:

```powershell
"버전:  " + (Get-Content "$env:LOCALAPPDATA\Programs\Robo-Architect\resources\runtime\runtime-manifest.json" -Raw | ConvertFrom-Json).releaseId
"도커:  " + (docker info --format "{{.ServerVersion}}")
"서비스: " + (docker ps --filter "label=com.docker.compose.project=robo-architect-desktop" -q | Measure-Object).Count + " 개"
```

## 10. 백업

### ⚠ 먼저 — **설계 데이터는 내 PC 에 없습니다**

중앙 DB 구성(§3 의 접속값)에서는 프로젝트·설계·권한이 **관리자의 서버**에 있습니다.
§6 에서 `graph-db`·`graph-bolt` 를 안 띄운 것이 그 뜻입니다.

```text
팀의 설계 전부   서버의 볼륨 `robo-central_graph_data`
                 → **관리자가 백업합니다**(`관리자-DB올리기.md` §9)
                 내 PC 에서 아무리 백업해도 **거기엔 설계가 없습니다**
내 PC 에 있는 것  앱 설정·비밀·로그, 그리고 적재 중간 파일뿐
```

이 절을 그대로 따라 하고 **설계를 백업했다고 믿으면 안 됩니다.**

### 내 PC 에서 백업할 것 — **두 조각을 함께**

```
① 이 PC 의 Docker 볼륨 둘
     robo-architect-desktop_shared_data     적재 중간 파일

② 앱 설정 폴더 통째로
     C:\Users\<계정>\AppData\Roaming\robo-architect-desktop\
       secrets\        암호화된 비밀번호
       Local State   ★ 그것을 푸는 열쇠 — 이것이 빠지면 ①에 못 붙습니다
       settings.json   저장된 연결
```

**한쪽만 백업하면 복구되지 않습니다.** 실제로 겪은 문제입니다.

> ⚠ **옛 판에서 깔았다면 `_mindsdb_data` 볼륨이 남아 있습니다.** 2026-10-27
> 판부터는 그 볼륨을 쓰지 않습니다. 지우지 않고 두어도 앱에 영향이 없고,
> 예전 판으로 되돌릴 때 필요합니다. 그 안에 **예전에 만든 데이터 소스 연결**이
> 들어 있습니다.

> **혼자 쓰는 구성(bundled)이라면** 볼륨이 하나 더 있습니다 —
> `robo-architect-desktop_graph_data` 에 **설계가 들어 있습니다.** 아래 목록에
> 그 이름을 더하십시오. 중앙 DB 를 쓰면 그 볼륨은 **아예 생기지 않습니다.**

### 백업하기

```powershell
$B = "D:\robo-backup-$(Get-Date -Format yyyyMMdd)"
New-Item -ItemType Directory -Force -Path "$B\volumes" | Out-Null

# 이 PC 에 **실제로 있는** 볼륨만 뜬다 — 없는 이름을 적으면 조용히 빈 파일이 생긴다
$have = docker volume ls --format '{{.Name}}' | Where-Object { $_ -like 'robo-architect-desktop_*' }
$have
foreach ($v in $have) {
  docker run --rm -v "${v}:/from" -v "${B}\volumes:/to" alpine:3.19 tar -czf "/to/$v.tgz" -C /from .
}

Copy-Item "$env:APPDATA\robo-architect-desktop" -Destination "$B\appdata" -Recurse -Force `
  -Exclude 'robo-images.tar'

Get-ChildItem $B -Recurse -File | Measure-Object Length -Sum |
  ForEach-Object { "{0} 파일 · {1:N1} MB" -f $_.Count, ($_.Sum/1MB) }
```

**이렇게 나와야 합니다**: 중앙 DB 구성이면 볼륨 이름이 **둘**. `graph_data` 가
목록에 보이면 **혼자 쓰는 구성**입니다 — §3 의 접속값이 안 먹은 것일 수 있으니 확인하세요.

> 앱을 **끄고** 하세요. 켜진 채로 뜨면 데이터베이스가 쓰는 중일 수 있습니다.

### PC 를 옮길 때

①과 ②를 **같이** 옮깁니다. `Local State` 는 Windows 계정에 묶여 있어서, **다른
계정으로 옮기면** 비밀번호를 다시 맞추는 절차가 필요합니다 —
`app-operations.md`(가이드 폴더가 아니라 **그 위 폴더**) 의 백업 절에 있습니다.

> 없으니** 백업(§10) 뒤에 하세요.
>
> ⚠ **서버의 `robo-central_graph_data` 는 건드리지 마십시오.** 거기에 팀 전체의
> 설계가 있습니다 — 내 PC 를 지우는 일과 아무 상관이 없습니다.

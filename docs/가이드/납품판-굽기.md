# 만드는 사람 — **POSCO SWP 납품판을 굽는다**

```text
이 문서가 다루는 것   `-rdel-swp` 판을 굽는 일 **하나**
다루지 않는 것        깔기(`사용자-설치-가이드.md`) · 중앙 DB(`관리자-DB올리기.md`)
언제 보나             SWP 등록값을 받은 뒤. **AI 키는 없어도 구워진다**(§2)
전제                  저장소 전부 작업 트리 **0건** · Docker 켜짐 · 디스크 20GB
```

> **지금까지 구운 것은 전부 시험판(`-rint-none`)이다.** 납품판은 **한 번도 구운
> 적이 없다**(2026-10-29 기준 `_releases` 일곱 판 전부 `-rint-none`).

## 0. 무엇이 다른가 — **릴리스 id 에 박힌다**

```text
robo.ps1 의 `$channelTag`   채널 'delivery' 면 'del' · 아니면 'int'
robo.ps1 의 `$releaseId`    {버전}-w{workspace}-a{architect}-s{지문}-r{채널}-{provider}
  ⓘ 줄 번호로 적지 않는다 — 이 파일은 자주 자라서 번호가 썩는다(실제로 겪었다)

지금까지        0.1.0-w…-a…-s…-**rint-none**
납품판          0.1.0-w…-a…-s…-**rdel-swp**
```

⚠ **환경변수로 SWP 를 켤 수 없다.** 자세가 굽기 때 박히므로 **다시 굽는 수밖에
없다.** 시험판을 현장에 들고 가도 SSO 로는 못 들어간다.

```text
관문이 거는 조건 (channel 이 internal-test 가 아닐 때)
  AUTH_ENFORCE        true 여야 한다            ← 아니면 거절
  AUTH_PROVIDER       none 이면 안 된다         ← 아니면 거절
  AUTH_CALLBACK_ALLOWLIST  ⚠ **비워 둔다**(아래 §1 ② 를 읽어라) — 경고만 뜬다
  AUTH_DEV_LOGIN_ENABLED   **true 면 거절**(`must not be packaged`) — 시험 로그인은 굽지 않는다
```

## 1. 굽기 전 — `robo-workspace\.env` 에서 고칠 줄

> ⚠ **이 파일은 이 PC 에만 있다**(git 이 추적하지 않는다). 그래서 **고친 뒤에
> 되돌려 놓는 일까지** 한 묶음이다 — 안 되돌리면 다음 시험 굽기가 사내 주소를
> 들고 나가고, 이 PC 는 거기에 못 닿는다. §5 를 먼저 읽는다.

### ① 자세 — 세 줄

```text
ROBO_RELEASE_CHANNEL=            ← **비운다**(비면 기본이 delivery · `Get-ReleaseAuthPosture`)
AUTH_PROVIDER=swp                ← 별칭 posco 도 같다
AUTH_DEV_LOGIN_ENABLED=false     ← 이미 false. **true 로 두면 거절된다**
```

### ② SWP 등록값 — ✔ **아홉 개 전부 비워 둔다** (2026-10-29 확인)

```text
msa-ez/platform **v1.0.30** 의 `docker-compose.yml` 을 읽어 대조했다 —
그 아홉 값이 **우리 코드 기본값과 전부 같다**:
  SWP_SSO_REDIRECT_URL     http://swpsso.posco.net/idms/U61/jsp/redirect.jsp?redir_url=
  SWP_SSO_VALID_CHECK_URL  http://swpsso.posco.net/idms/U61/jsp/isValidSSO.jsp
  SWP_SSO_LOGIN_URL        http://swp.posco.net
  SWP_IDX_ID 0 · EMPNO 1 · DISPLAYNAME 8 · MAIL 9 · DEPT 4
  SWP_EMAIL_FALLBACK_DOMAIN  posco.local
⇒ **적을 필요가 없다.** 굽기는 비었다고 경고하지만 그 경고는 "기본값으로 돈다"
  는 뜻이고, 그 기본값이 **맞는 값**이다
⚠ 그래도 `SWP_IDX_*` 는 **칸 번호**다 — 현장 응답의 열 순서가 스펙과 다르면
  **엉뚱한 칸을 사번으로 읽고도 오류가 나지 않는다.** 첫 연동에
  `SWP_SSO_LOG_RAW=1` 로 원문을 한 번 찍어 눈으로 확인한다
```

```text
⚠⚠ `AUTH_CALLBACK_ALLOWLIST` 는 **비워 둔다**
  처음에 이 가이드는 "비우면 거부된다 · 관문이 거절한다" 고 적었다. **틀렸다.**
  `api/features/auth/config.py` 의 `is_allowed_callback()` 을 읽으면 —
    비면   loopback(localhost · 127.0.0.1 · ::1) **만** 허용
    있으면 origin 완전일치만, 그리고 **loopback 자동허용이 사라진다**
      (`test_swp.py`: 목록이 있으면 "http://localhost:5173/cb" is **False**)
  우리 앱은 각 PC 의 Electron 이고 백엔드가 `127.0.0.1:<동적 포트>` 다 —
  포트가 매번 바뀌니 **적을 수가 없다.** 채우면 **로그인이 깨진다.**
  ⇒ 중앙 authority 로 콜백이 돌아오는 구성이면 그때만 그 origin 을 적는다.
    어느 쪽인지는 **SWP 에 등록된 리다이렉트**가 정한다 — 현장에서 확인한다
  ⓘ msa-ez 에는 이 이름이 **아예 없다**(웹앱이라 자기 origin 으로 돌아온다)
  ⓘ 이름에 `SWP_` 가 붙지 않는다 — 양식의 `SWP_SSO_CALLBACK_ALLOWLIST` 는
    잘못 적힌 것이었고 **아무도 읽지 않았다**(2026-10-26 에 고쳤다)
```

### ③ AI 주소 — **P-GPT 로 바꾼다. 주소는 굽기 때 박힌다**

```text
OPENAI_BASE_URL=http://aigpt.posco.net/gpgpta01-gpt/v1     ⚠ **http** 다
LLM_API_BASE=http://aigpt.posco.net/gpgpta01-gpt/v1        (카탈로그)
ROBO_EMBED_API_BASE=http://aigpt.posco.net/gpgpta01-gpt/v1 (분석기)
ROBO_LLM_CONFIG=pgpt                                       (분석기 설정 파일 고르기)
LLM_MODEL=**gpt-4.1**                                      ✔ 2026-10-29 에 정했다
  근거: **이 조직이 실제로 쓰는 모델**이다 — msa-ez v1.0.30 이
  `AI_MODEL="openai:gpt-4.1-2025-04-14"` 를 쓴다. P-GPT 는 OpenAI 모델을
  공식 API 형식 그대로 중계한다. 받은 P-GPT 문서의 `gpt-5.2` 는 **예시**였다
  ⓘ 날짜 스냅샷은 OpenAI 가 **deprecated** 로 표시했으므로 별칭 `gpt-4.1` 을 쓴다
  ⚠ 그래도 현장에서 `GET {api_base}/models` 로 한 번 확인한다

ROBO_LLM_CONFIG=**pgpt**                                   분석기가 고르는 설정
ROBO_LLM_MODEL_RUNTIME_CAPABILITIES_REF / _SHA256          **봉인**
  ⚠⚠ 이 둘은 **모델마다 다르다.** 분석기가 매 실행 **전에** 이 파일의 바이트를
    검증한다(조건 없이 돈다 — 틀리면 분석이 죽는다).
    `gpt-4.1` 용 봉인을 2026-10-29 에 지었다:
      llm/capabilities/gpt41_openai_2025_04_14.yaml
      sha256 09904ac41504b7128588dd32ef0f8c2dabf80366209bcad3bca6d2c730055df8
      context 1,047,576 · max output 32,768 (OpenAI 모델 페이지에서 확인)
  ⚠ **그 전까지 이 둘이 config 와 어긋나 있었다** — config 는 gpt54_mini 인데
    ref 는 **qwen38** 을 가리켰고 sha 가 그 파일과 맞아서 **봉인이 통과했다.**
    그래서 아무도 불평하지 않은 채 **다른 모델의 한계**로 돌았다.
    ⇒ 모델을 바꿀 때는 **ref·sha·config 셋을 함께** 본다
  ⚠ 임베딩 **차원** — 코드에 박혀 있지 **않다.** 분석기가 `CREATE VECTOR INDEX`
    를 만들 때 **그 run 의 실제 벡터 길이**로 차원을 잡고, 엔진은 `vector(N)` 을
    임의의 N 으로 받는다. **그러나 이미 만들어진 DB 는 그 차원으로 굳는다** —
    2026-10-29 에 중앙 DB 를 재 보니 컬럼과 hnsw 색인이 **`vector(1536)`** 이었다
    (text-embedding-3-small 로 만들어졌다).
    ⇒ `-3-small` 로 가면 **이미 있는 그래프를 그대로 쓴다**.
      `-3-large`(3072)로 바꾸면 인덱스를 `IF NOT EXISTS` 로 만들기 때문에
      **옛 차원이 그대로 남고 자동으로 안 바뀐다** — 그래프를 새로 만들고
      **다시 분석**해야 한다. 모델은 **바꾸기 전에** 정한다
ⓘ 개발계는 http://taigpt.posco.net/gpgpta01-gpt/v1
```

> ```text

> ⇒ 창을 닫으면 백엔드가 내려간다. **컨테이너는 계속 돈다**(설계대로다).

### ④ 체크섬 — 적힌 값과 **직접 계산한 값**을 대조

```powershell
Set-Location $R
Get-Content .\SHA256SUMS | ForEach-Object {
  $p = $_ -split '\s+', 2
  $f = Join-Path $R ($p[1].Trim() -replace '/', '\')
  $h = (Get-FileHash -Algorithm SHA256 -LiteralPath $f).Hash.ToLower()
  "{0}  {1}" -f $(if ($h -eq $p[0].ToLower()) { '맞음' } else { '✘ 다르다' }), $p[1]
}
```

## 5. 되돌려 놓는다 — **잊으면 다음 시험 굽기가 깨진다**

```text
`robo-workspace\.env` 는 이 PC 에만 있고 git 이 안 본다. 그래서 고친 것을
**사람이 되돌려야** 한다. 납품판을 굽고 나면 §1 에서 바꾼 줄을 되돌린다 —

  ROBO_RELEASE_CHANNEL=internal-test
  AUTH_PROVIDER=none
  OPENAI_BASE_URL · LLM_API_BASE · ROBO_EMBED_API_BASE → https://api.openai.com/v1
  ROBO_LLM_CONFIG=gpt54_mini_openai
  AUTH_CALLBACK_ALLOWLIST · SWP_* → 비운다

⇒ 안 되돌리면 다음 시험판이 **사내 주소를 들고** 구워지고, 이 PC 는 거기에
  못 닿아 "AI 가 안 된다" 로 나타난다. 증상이 굽기가 아니라 **쓸 때** 나온다.
ⓘ 바꾸기 전에 `.env` 를 복사해 두면 되돌리기가 한 줄이다 —
  `Copy-Item .env .env.bak.rint`  … 되돌릴 때 `Copy-Item .env.bak.rint .env`
```
